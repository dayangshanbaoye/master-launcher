## 最大的杠杆：图标单色化

把所有 adaptive icon 抽成单色描边，统一染成次级文本色。品牌色一去掉，屏幕从"广告牌"变成"目录"，排序结果的差异成为唯一的视觉信息。

这一条比任何配色方案都重要。

延伸结论：**Browse 里干脆不放图标**。单色的微信和单色的 QQ 形状高度接近，图标失去品牌色后不再承载识别功能，只剩噪音；中文 app 名 2–4 字，读字比认抽象轮廓快。Canvas 和 Search 保留单色图标（条目少，图标辅助定位），Browse 纯文字。

## 颜色

| 角色 | 暗色 | 亮色 |
|---|---|---|
| 背景 | `#14100E` 暖黑（非纯黑，OLED 近黑但不刺眼） | `#FAF6F0` 纸白 |
| 主文本 | `#EDE6DC` | `#26221E` |
| 次文本 | `#8C837A` | `#6E665E` |
| 边框 | `#2A2320` | `#E5DDD3` |
| 强调 | `#C97A40` | `#C97A40` |

强调色**只用于两处**：当前选中项、引擎主动提议。其余一律不用。

## 字体

- 中文思源黑体，字重只用 Light(300) 和 Regular(400)，不用 600 以上
- 数字用 tabular-nums
- 字号：主条目 13sp / 次要信息 11sp / 时间 26sp。只有这三级

中英混排时英文名与中文名同字号、同字重——`Kindle` 和`豆瓣`视觉重量一致才对。

## 间距与密度

| 元素 | 值 |
|---|---|
| 屏幕左右留白 | 20dp |
| Search 结果行高 | 56dp |
| Browse 条目行高 | 44dp，间距 7dp |
| Browse 左栏宽 | 76dp（放得下 3 个中文字） |
| 圆角 | 8dp（条目）/ 16dp（Sheet） |
| 边框 | 0.5dp |

Search 一屏最多 6 条，Browse 一屏 7–8 项。超出说明排序没做好，不靠滚动解决。

## 装饰

无阴影、无渐变、无卡片填充色。**分隔靠留白，不靠线。**

选中态用边框加重（0.5dp → 1dp）表达，不用色块——单色目录里边框粗细就够了。

## 动效

```kotlin
spring(dampingRatio = 0.85f, stiffness = 400f)
```

- Sheet 上滑跟手，不用 tween
- 手势识别阈值 48dp / 上限 300ms
- 分类切换用左右滑，不用点
- 尊重系统的"减少动画"设置

## 文案

- 一律句式简短、动词开头、无标点结尾
- 空结果不道歉，直接给下一步："在浏览器中搜索 wxds"
- 匹配原因用最短表述："首字母" / "今天 3 次" / "快捷方式"
- 不出现"成功""请""正在为您"
