# 1 · 手势系统

## 1.1 实测修正

上一版对单指左右滑给出了"与系统返回区冲突、失败率高"的判断。**实测不成立，收回。**

原因是系统返回区只有屏幕左右边缘约 20dp，而右手拇指的自然滑动起手点落在屏幕中下部，天然避开了边缘。这条约束在**"从边缘起手"**的场景才成立，日常单手拇指操作不会撞上。

保留一个已知边界：少数 ROM 会把返回区加宽，或用户习惯从最边缘起手。处理方式是在手势速查表里提供单条开关，出问题的设备可关掉左右滑，不做全局妥协。

四角对角滑仍然移除——那是真实失败，根因是对角方向识别区间与直线重叠，且角落需要拇指重新定位。

## 1.2 手势映射表

单指承担全部核心导航，双指只保留一个。

| 手势 | 目标 | 依赖 |
|---|---|---|
| 单指下滑 | Search | 无 |
| 单指右滑 | 下一页（Canvas → Browse） | 无 |
| 单指左滑 | 返回上一页 | 无 |
| 单指上滑 | 最近任务 | 无障碍 |
| 双击空白 | 回首页 | 无 |
| 双指下滑 | 通知栏 | 无障碍 |
| 长按空白 | 手势速查表 | 无 |

**双指只有一个手势。** 上一版给 Search 绑了单指上滑和双指下滑两条路径，既然下拉已经承担了 Search，重复绑定只增加记忆负担、不增加能力，取消。双指的价值在于它是唯一不受系统边缘限制的通道，留给通知栏——这是单指最难安全实现的动作（顶部下拉必然与状态栏抢），也与"下拉"的方向语义天然一致：单指下拉出应用搜索，双指下拉出系统通知。

如果不想授权无障碍，双指下滑可在速查表里改绑锁屏（同样需无障碍）或留空。**未授权时该手势不绑任何动作，也不弹窗骚扰。**

## 1.3 导航模型

Canvas 是原点，surface 之间是一条线性栈：

```
        ┌── 单指下滑 ──→ Search
        │
Canvas ─┼── 单指右滑 ──→ Browse
        │
        └── 单指上滑 ──→ 最近任务（离开本应用）

任意页 ── 单指左滑 ──→ 返回上一层
任意页 ── 双击空白 ──→ 直接回 Canvas
```

- Canvas 上左滑无动作（已在栈底），不做任何反馈动画，静止即是答案
- Browse 内右滑无动作（不再有下一页）
- 双击是"逃生出口"，从任何深度一步回家，这是单手操作时最重要的一条

## 1.4 单手右拇指优化

这是本轮的主要优化方向。右手持机、拇指操作时，触达难度从易到难大致是：右下 → 中部 → 右上 → 左中 → 左上。

**判定参数按拇指弧线调整**

拇指横扫的轨迹是弧线不是直线，末端会向上翘。因此：

| 参数 | 值 | 说明 |
|---|---|---|
| 方向判定 | 起点→终点向量，不看中间轨迹 | 弧线中段会偏离目标方向，看轨迹必误判 |
| 左右容差 | ±40° | 横扫弧度最大，放宽 |
| 上下容差 | ±30° | 纵向轨迹更直 |
| 主轴比 | 主方向位移 / 次方向位移 > 1.7 | 达不到就不判定 |
| 距离阈值 | 48dp | |
| 时间上限 | 300ms | |
| 双击窗口 | 250ms | |
| 长按触发 | 400ms | |
| 双指判定 | 两指落点间距 ≥ 60dp 且落点时间差 < 120ms | |

**超出容差不做最近邻猜测，直接不响应。** 没响应的代价是原地重滑一次；猜错的代价是打开了不想要的东西再退出来。后者高得多。

**布局侧的三条规则**

1. **左上角不放任何交互元素。** 右手拇指最难触达，放什么都是摆设。
2. **右上角的设置按钮必须有第二条路径。** 右上是次难点，需要换手或够一下。长按空白唤出的速查表底部提供"设置"入口，让常用路径落在拇指舒适区。
3. **惯用手开关。** 设置里提供"惯用手：右 / 左"，决定 8 槽中固定簇与推荐簇的左右分布——引擎推荐簇（高频）放在惯用手一侧的下角，即拇指最舒适区。

**双击的实现纪律**

启用双击后，参与判定的区域所有单击都要等 250ms。因此：

- 双击判定**只挂在空白区**的 touch listener 上
- app 槽、设置按钮、相册区走独立的即时点击通道，不参与双击判定，点击零延迟
- 不要在根 View 挂全局 `GestureDetector`，那会让整个首页点击慢 250ms，这是用户能直接感知的手感损失

## 1.5 手势速查表

长按空白处唤出，半透明浮层，松手消失。

- 显示当前全部绑定，包括未授权而失效的项（灰显 + "需授权"）
- 每条可就地改绑
- 底部提供"设置"入口
- 不做常驻提示、不做首次引导弹窗——手势是给记住的人用的，速查表是给忘了的人用的

# 2 · 首页 Canvas

## 2.1 布局

```
┌────────────────────────────┐
│                      [设置] │
│         09:41              │  ← 时钟区，元素可勾选
│      周三 · 8月12日          │
│                            │
│   ┌────────────────────┐   │
│   │   海报 / 相册墙      │   │  ← 展示区
│   └────────────────────┘   │
│                            │
│  固定簇 4        推荐簇 4    │  ← 左右分布由惯用手决定
└────────────────────────────┘
```

## 2.2 时钟区

**四个元素，勾选组合决定排布。**

| 元素 | 可否取消 |
|---|---|
| 时间 | 否，恒显示 |
| 星期几 | 可 |
| 日期 | 可 |
| 农历 | 可 |

**固定 24 小时制，不提供 12 小时选项。**

副元素的相对顺序固定为 `星期 · 日期 · 农历`，用户只能决定显示与否，不能调顺序——顺序是设计过的，交给用户就变成又一个设置项。

**排布规则由副元素个数决定：**

| 副元素数 | 排布 |
|---|---|
| 0 | 时间 48sp Light，垂直居中偏上，无副行 |
| 1 | 时间 32sp + 副行 12sp |
| 2 | 时间 32sp + 副行 12sp，两元素用 ` · ` 连接 |
| 3 | 时间 32sp + 第一副行 `星期 · 日期` + 第二副行 `农历`，均 11sp |

副元素为 3 时拆成两行，是因为 `周三 · 8月12日 · 六月十九` 单行过长会与 26sp 的时间抢视觉重量。拆行后时间仍是唯一焦点。

**渲染细节**

- 数字用 tabular-nums，避免分钟跳变时整行宽度抖动
- 分钟变化只重绘时间文本，不重组整个时钟区
- 农历计算走本地表，不联网

## 2.3 应用槽（8 个）

**固定簇 4 个：用户钉死，引擎永不改动。**
**推荐簇 4 个：引擎选择。**

左右分布由「惯用手」开关决定，推荐簇落在惯用手下角（拇指最舒适区）。

**推荐簇必须加迟滞：**

```
替换在位者的条件：连续 3 天 frecency 得分 > 在位者 × 1.2
```

纯 top-N 会让位置天天变，用户建不起肌肉记忆——而"Gesture when you remember"整条哲学建立在肌肉记忆上。**引擎越勤快，这一栏越没法闭眼点。** 迟滞是必需项不是优化项。

发生替换时只换那一个位置，簇内其余顺序不动。

**交互**

| 操作 | 效果 |
|---|---|
| 长按固定槽 | 更换 / 清空 |
| 长按推荐槽 | 钉住（转入固定簇，需挤掉一个，弹确认）/ 排除（30 天内不再推荐） |
| 点击空槽 | 进入 Search 选择 |

空槽显示虚线框，不自动填充。

## 2.4 设置入口

**纪律条款：设置页只放系统级开关。** 排序权重、分类规则、匹配阈值、迟滞天数等引擎参数一律不进设置，由引擎自决或通过长按就地调整。这条不守住，三个月后这里会长成 300 项的设置树。

| 分组 | 条目 |
|---|---|
| 桌面 | 选择默认桌面（跳系统页）/ 设为默认桌面 |
| 手势 | 惯用手、无障碍授权状态与引导 |
| 时钟 | 四元素勾选 |
| 相册 | 显示模式、来源文件夹、切换时机 |
| 数据 | 导出配置 / 导入配置 |
| 关于 | 版本、开源许可 |

**技术说明**：Android 不提供直接切换默认启动器的 API。

- 切回原生：`Intent(Settings.ACTION_HOME_SETTINGS)`，用户手动选
- 设回本应用：Android 10+ 用 `RoleManager.createRequestRoleIntent(ROLE_HOME)`，一次性对话框直接确认

按钮文案写「选择默认桌面」而不是「切换桌面」——诚实描述实际发生的事。

## 2.5 展示区

**模式一 · 海报**

- 全宽单图，圆角 12dp
- 图片来源为一个本地文件夹（ChatGPT 生成的海报放进去即可，不集成任何 API）
- 切换时机：**每次解锁**（默认）/ 每天一次 / 手动
- **不做自动轮播动画**。常驻动画耗电、持续抢注意力、且与手势争夺触摸区。改成解锁时换图后，每次点亮屏幕都是新的一张，惊喜感更强，成本几乎为零
- 点击 → 进入全屏查看器

**模式二 · 相册墙**

- 3×2 或 3×3 小图网格，每张带 2dp 内描边模拟相框，间距 8dp
- 选择此模式时 **app 槽自动减为 4 个（仅保留固定簇）**——一屏一个视觉重心，相框墙和 8 个槽同时存在会互相打架
- 墙本身不翻页、不动，全部照片一次性呈现
- 点击任一张 → 进入全屏查看器

**全屏查看器（两种模式共用）**

- 点击照片进入，共享元素过渡（相框位置放大到全屏）
- **该层独占触摸，全局手势全部挂起**
- 左右滑 = 上一张 / 下一张，范围是当前墙上的那几张，到头不循环（末端给轻微阻尼回弹）
- 下滑 / 系统返回键 / 点击图外空白 = 关闭，**回到墙时定位到刚才那一张的位置**
- 双击 = 1x / 2x 缩放，双指捏合自由缩放
- **不做删除、编辑、分享、收藏**——一旦有这些，它就开始长成一个图库 app

**展示区不承载功能。** 除翻页和放大外不可交互。一旦允许它放天气、日程、快捷操作，首页就退化成控制面板，整套设计的前提就没了。

# 3 · 搜索与浏览

## 3.1 Search

### 3.1.1 空态：目标排行榜

搜索框未输入时展示排行榜。

**核心决策：按 Target 聚合，不按搜索词聚合。**

用户搜 `wx`、`weixin`、`微信` 是同一件事。按词统计会把一个目标拆成三条，排行榜立刻失真。按目标聚合才回答用户真正的问题——"我最常开什么"。

```
本周最常打开
─────────────────────
1  微信读书        23 次
2  微信            18 次
3  高德地图        11 次
...
```

- 时间窗口 chips：今天 / 本周 / 本月，默认本周
- 显示前 10 条
- **只统计从 Search 打开的**，不混入手势和首页槽的启动次数，否则排行榜会被首页 8 槽刷屏，失去信息量

**排行榜是配置入口。** 长按条目：

| 操作 | 效果 |
|---|---|
| 绑定手势 | 直接进手势选择 |
| 钉到首页 | 加入固定簇 |
| 改别名 | 写入 aliases，永久生效 |
| 不再统计 | 从排行榜隐藏 |

排行榜因此承担三个职责：满足好奇心、补手势可发现性的洞、替代设置页。**它是引擎向用户展示自己的窗口。**

### 3.1.2 搜索词历史

搜索词历史和目标排行是两个东西。真正有价值的不是"搜过什么"，而是**"搜了但没打开任何东西"**——那说明索引或别名缺失。

- 失败查询单独收集
- 同一失败词累计 3 次，浮一次提示："搜过 3 次『追剧』没结果，要给某个应用加这个别名吗？"
- 这是别名系统的自动生长机制，比让用户主动配别名有效得多

普通历史词在输入框获焦但未输入时，作为第二块区域展示最近 5 条，可单条删除、可一键清空。

### 3.1.3 结果区

- 上限 6 条，不滚动
- 每条显示匹配原因（"首字母" / "今天 3 次" / "快捷方式"）
- 回车 / 语音停顿 600ms 锁定第一项
- 无结果时末条给"在浏览器中搜索 xxx"
- **键盘弹起时结果区不上移**：结果从搜索框下方向下排列，键盘遮住的是空白而不是结果。单手操作时这一条尤其重要——结果和拇指在同一区域

### 3.1.4 语音

- 识别失败或误识别时**保留已识别文本**，直接切键盘继续改，不清空重来
- 无网络 / 无识别引擎时麦克风置灰并显示原因，不要点了没反应
- partial result 节流 200ms，且只在文本真正变化时触发 query

## 3.2 Browse

### 3.2.1 自动分类：六层来源

`ApplicationInfo.category` 在国内 app 上覆盖率低且常填错，不能单独依赖。

| 优先级 | 来源 |
|---|---|
| 1 | 用户覆盖（持久化，永远最高） |
| 2 | 内置映射表（人工维护国内 top 500 包名 → 分类，随版本更新） |
| 3 | `ApplicationInfo.category` |
| 4 | 名称关键词规则（"阅读/读书/小说" → 阅读；"银行/支付" → 金融） |
| 5 | 行为聚类 |
| 6 | 未分类 |

**行为聚类是"真正自动"的关键**：统计启动时段分布和连续启动关系（A 打开后 5 分钟内常开 B），行为相似的聚在一起。通勤时段连用的自然聚成出行，晚上连用的聚成阅读。

冷启动无数据，所以静态表打底、聚类做修正。**聚类结果只用于给未分类项打标和提示改标，不自动推翻已有分类**——悄悄改动用户已经熟悉的分类是最伤信任的行为。

**可选的一次性 LLM 打标**：首次配置时可选择把 app 名单（仅名称，不含使用数据）发给模型返回分类建议。明确告知联网、可跳过、结果逐条可改。不做常驻联网。

### 3.2.2 多分类归属

**架构已支持**——`Target.tags` 当初定义成 `Set<Tag>` 而非单值，不需要改数据模型。

产品上要让用户明确感知"这不是文件夹"：

- 编辑用**多选勾选**，不用拖拽移动
- 从任一分类进入都能找到
- 同一 app 在不同分类下的排序独立计算

**默认策略：自动分类只给一个主分类，多分类由用户主动添加。** 自动多标会让每个分类都塞满，Browse 的筛选价值归零。

### 3.2.3 分类编辑

- **单条**：长按条目 → 所有分类的多选列表，勾选即生效，无需确认
- **批量**：长按进多选模式 → 选一批 → 底部"添加到分类 / 移出分类"
- **拖拽**：支持从右栏拖到左栏分类上。但拖拽在语义上暗示"移动"，与多归属冲突，因此落下时显示"已添加到 X（仍在 Y、Z 中）"的短提示，用文案纠正心智
- **自定义分类**：允许创建，**上限 8 个**；成员数 < 3 时不在左栏显示，只在编辑界面可见。既满足灵活，又防止左栏长出一堆单成员分类——那正是传统文件夹的失败模式
- **未分类**：左栏底部显示"未分类 (6)"，可批量处理，数量为 0 时该项消失

### 3.2.4 排序与索引

- 分类内按 frecency 排序，不按字母
- 仅"全部"分类挂拼音首字母索引条
- 共同前缀条目（"某某极速版" / "某某HD"）差异部分渲染为次级色后缀
- 左栏分类顺序按该分类总启动频次排，**每周重算一次**，不要每天变

# 4 · 性能、异常与边界

本章集中所有非功能性要求。第 1–3 章的功能实现完成后，逐条对照本章验收。

## 4.1 性能预算

| 指标 | 预算 |
|---|---|
| 冷启动到首帧可交互 | < 150ms |
| 索引快照反序列化 | < 20ms |
| 单次 query（500 条目） | < 8ms |
| 手势判定到 surface 开始转场 | < 16ms（一帧） |
| 语音 partial 刷新间隔 | 200ms |

**首帧预算只覆盖「时间 + app 槽可交互」**，展示区图片不计入，但必须在首帧之后异步填充。

建立三条 CI 断言，任一超标拒绝合并：

```
assert 冷启动到首帧可交互 < 150ms
assert 索引反序列化 < 20ms
assert query(500) < 8ms
```

超预算就去修实现，不加骨架屏掩盖。

## 4.2 冷启动空数据（最高优先级）

新用户第一次进来，frecency 无数据，8 槽是空的，排行榜是空的。**这是第一印象，也是最大流失点**——整套产品的卖点是"引擎很聪明"，第一分钟给不出证据，用户不会等你学七天。

- 引导页让用户直接选 4 个钉到固定簇，候选从系统使用统计预填
- 可选申请 `PACKAGE_USAGE_STATS`（需跳系统设置授权）导入历史使用数据，一次性冷启动 frecency
- 拒绝授权则推荐簇前 7 天显示"正在学习你的习惯"占位

**绝不用随机或字母序填充 8 个槽。** 用户会立刻判定这个启动器不聪明，这个判断很难翻盘。

## 4.3 展示区资源管理

| 项 | 要求 |
|---|---|
| 解码 | 按显示尺寸 `inSampleSize` 降采样，绝不加载原图 |
| 缓存 | 磁盘缓存已解码缩略图，冷启动直接读 |
| 内存 | 海报模式同时驻留 ≤ 2 张（当前 + 预取下一张）；相册墙模式驻留全部缩略图，但缩略图边长 ≤ 显示尺寸 × 2 |
| 全屏查看器 | 进入时才解码高分辨率版本，退出立即释放 |
| 首帧顺序 | 时间 + app 槽先上屏 → 展示区占位纯色块 → 图片异步填充 |

**不要为了让展示区和内容同时出现而阻塞首帧**，那会把 150ms 变成 600ms，是最糟的取舍。

## 4.4 进程被杀与重启

国产 ROM 会杀启动器进程。被杀后按 Home 回来白屏 0.5–2 秒，是体感最差的场景。

- 索引快照必须能在 20ms 内反序列化，不依赖网络、不依赖重建
- 首帧只画时间和 app 槽，数据来自快照
- **不做进程保活，做快启动**

## 4.5 权限矩阵与降级

| 权限 | 用途 | 未授权时的行为 |
|---|---|---|
| 无障碍 | 最近任务、通知栏、锁屏 | 相关手势不绑定任何动作，速查表中灰显"需授权"，**不弹窗骚扰** |
| `PACKAGE_USAGE_STATS` | 冷启动导入历史 | 推荐簇显示"正在学习"占位 |
| 通知监听 | 角标未读 | 不显示角标区域，不留空位 |
| 读取媒体 | 相册来源 | 展示区显示"选择图片文件夹"引导 |

**核心三入口（Search / Browse / Canvas）零权限依赖**，任何权限被拒都不影响主功能。

**无障碍失效自检**：国产 ROM 后台清理会静默关闭无障碍服务。开机和每次回到 Canvas 时检查一次服务状态，失效则在速查表里标注，不做浮窗提醒。

## 4.6 默认桌面被重置

国产 ROM 系统更新后常重置默认桌面。开机自检当前默认 Home，被改了在首页浮一条低干扰提示（一行文字 + 一个跳转按钮，可划掉，7 天内不重复）。

## 4.7 备份与迁移

手势绑定、别名、分类覆盖、钉选槽位、时钟配置、相册设置全在本地。丢了等于从零开始，而这些恰恰是用户投入最多的部分。

- 导出为单个 JSON（走 SAF，用户自选位置）
- 导入做版本兼容和冲突提示
- 每 7 天静默生成本地快照，保留最近 3 份

## 4.8 角标与未读

从原生桌面迁过来最常见的抱怨。

- 通过 `NotificationListenerService` 读角标（可选权限）
- 样式为条目右侧 4dp 圆点，**不显示数字**——数字是噪音，"有没有"才是信息

## 4.9 折叠屏与横屏

- 展开态：8 槽改为两侧各 4 竖排，展示区居中占更大比例
- 横屏：Browse 的 master-detail 天然适配；Canvas 把时钟移到左侧，展示区右侧
- 至少保证不崩、不裁切，不追求最优布局

## 4.10 无障碍（TalkBack）

- **所有手势必须有等价的可点击入口**——TalkBack 用户无法执行自定义手势
- app 槽、相框必须有 `contentDescription`
- 尊重系统"减少动画"设置，关闭共享元素过渡，改为直接切换
